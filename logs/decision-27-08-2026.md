## 2. Key Architectural & Design Choices

### 2.1. Time-Domain Matched Filter over FFT
- **Decision:** Utilize a time-domain correlator (Matched Filter) with an adder tree rather than an FFT-based Parallel Code Phase Search (PCPS) for the tracking stage.
- **Rationale:** For a single, already-acquired GPS L1 C/A channel (1023 chips), a time-domain approach is significantly more resource-efficient in FPGA fabric (LUTs/DSPs) and introduces lower, deterministic latency compared to instantiating large FFT IP cores and managing complex BRAM ping-pong buffers.

### 2.2. Fixed-Point Arithmetic (Q-Format) Standardization
- **Decision:** Standardize internal datapath widths to prevent overflow and truncation errors.
  - **Input Samples:** 16-bit signed (`Q1.15`)
  - **NCO Sine/Cosine:** 18-bit signed (`Q1.17`, scaled to ±131,071)
  - **Mixer Output:** 18-bit signed (truncated from 34-bit multiply-accumulate with arithmetic right shift)
  - **Correlator Accumulators:** 32-bit signed (`Q16.16` equivalent for dynamic range up to ±2 billion, safely handling 4000 samples × max input values).

### 2.3. Mirror-Image Synthetic Stimulus Generation
- **Decision:** Instead of using naive sawtooth waves or external binary files for testbenches, instantiate the *exact same* `code_nco`, `ca_code_gen`, and `carrier_nco` modules inside the testbench (`gps_signal_gen.v`) to generate the input signal.
- **Rationale:** This guarantees that the stimulus perfectly matches the receiver's expected frequency words and code phases, isolating tracking logic bugs from stimulus generation errors.

## 3. Critical Bugs Identified & Resolved

| # | Issue | Root Cause | Resolution |
|---|-------|------------|------------|
| **1** | **Perpetual Reset** | ZedBoard push-buttons are Active-High, but RTL expected Active-Low (`!rst_n`). | Added `wire rst_n_internal = ~rst_n;` in `tracking_top.v` and routed this to all sub-modules. |
| **2** | **Uninitialized ROM ('x' outputs)** | `$readmemh` used a relative path. XSim runs in a hidden directory and could not find `ca_code_all_prns.hex`. | Updated to an **absolute path**: `/home/johan2/.../ca_code_all_prns.hex`. |
| **3** | **Code NCO Wrap Collision** | Non-blocking assignments (`<=`) caused `chip_idx` to sample `code_phase` *before* the 1023-chip wrap-around logic executed. | Introduced a combinational `next_phase` variable. Assigned both `code_phase` and `chip_idx` from `next_phase` in the same clock cycle. |
| **4** | **Early/Late Index Overflow** | 10-bit arithmetic for `chip_idx_p ± 512` caused modulo-1024 wrap-around, making Early and Late indices identical (e.g., `100 - 512 = 612` and `100 + 512 = 612`). | Upgraded Early/Late calculation to **11-bit math** with explicit `>= 1023` conditional wrapping to maintain true ±0.5 chip separation. |
| **5** | **Frequency Word Mismatch** | The testbench carrier/code frequency words did not mathematically align with the 4 MHz sample rate assumption of the tracking channel. | Recalculated and aligned `CARR_FREQ_WORD` (`48'h000010624DD2F1` for 1kHz) and `CODE_FREQ_WORD` (`32'h4178D4FD` for 1.023MHz). |

## 4. Final Simulation Verification Metrics
After applying all fixes, the 10ms behavioral simulation yielded the following verified results:
- **Prompt Correlation (`I_P`):** Stabilized at a strong peak of **~1,071,137** (validating successful carrier wipe-off and code alignment).
- **Early/Late Separation:** `I_E` (~2,816,105) and `I_L` (~1,549,535) are now distinctly different, proving the Delay Lock Loop (DLL) discriminator will have a valid error gradient to drive code phase adjustments.
- **Carrier Phase:** The 48-bit `carrier_phase_int` accumulator increments smoothly and predictably, validating the NCO pipeline.
- **Status Indicators:** The `led_tracking_ok` logic successfully triggers when `I_P` exceeds the defined threshold.
