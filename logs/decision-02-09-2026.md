**Date:** Wednesday, September 2, 2026

## 📋 Executive Summary

This document captures all critical design decisions made during the development and debugging of the FFT-based GNSS acquisition engine. The design implements a **Parallel Code Phase Search (PCPS)** algorithm using frequency-domain circular cross-correlation, matching the mathematical core of industry-standard receivers like GNSS-SDR and Pocket SDR.

---

## 🏗️ 1. Top-Level Architecture Decisions

### Decision 1.1: Frequency-Domain vs. Time-Domain Correlation
**Choice:** Frequency-domain (FFT-based) correlation  
**Rationale:**
- Time-domain correlation requires O(N²) operations = 16.7 million ops per PRN
- FFT-based approach reduces to O(N·log₂N) ≈ 49,000 ops per PRN
- **340× computational savings** for 4096-point FFT
- Enables parallel code phase search (all 4096 phases evaluated simultaneously)

### Decision 1.2: Dual Clock Domain Architecture
**Choice:** 100 MHz write clock / 200 MHz read clock  
**Rationale:**
- ADC interface typically runs at 100 MHz (4 Msps GPS L1 C/A)
- FFT processing benefits from higher clock (200 MHz) to meet timing
- Async FIFO provides clean CDC boundary with proper handshake signals
- Eliminates metastability risks at clock domain crossing

### Decision 1.3: 18-bit Signed Data Path
**Choice:** 18-bit signed throughout the pipeline  
**Rationale:**
- Matches Xilinx DSP48E1 native multiplier width (18×18 → 36-bit product)
- Provides sufficient dynamic range for GPS signals (~100 dB)
- Sign-extended from 16-bit ADC input with 2 guard bits
- Prevents overflow in complex multiplication stage

## 🔄 2. FFT Wrapper Design Decisions

### Decision 2.1: Xilinx FFT IP Configuration
**Choice:** Radix-4 Burst I/O, 4096-point, 18-bit input, Block Floating Point  
**Rationale:**
- **Radix-4 Burst I/O:** Best area/speed tradeoff for 4096-point FFT
- **Block Floating Point (BFP):** Automatically scales internal data to maximize dynamic range without user intervention
- **4096-point:** Matches GPS L1 C/A code length (1023 chips) padded to power-of-2 for FFT efficiency
- **18-bit input:** Matches DSP48E1 native width

### Decision 2.2: 8-bit Configuration Vector Format
**Choice:** `{4'd12, 3'b000, inverse}` for `s_axis_config_tdata`  
**Rationale:**
- Per Xilinx PG109 (FFT v9.1 Product Guide):
  - Bits [7:4]: NFFT = 12 (since 2^12 = 4096)
  - Bits [3:1]: CP_LEN = 0 (no cyclic prefix)
  - Bit [0]: FWD_INV (0 = forward, 1 = inverse)
- **Critical Bug Found:** Initial implementation had reversed bit ordering, causing FFT IP to interpret NFFT=0 and silently stall
- **Fix:** Corrected to match PG109 Table 3-5 specification

### Decision 2.3: Separate Counters for LOAD and UNLOAD States
**Choice:** Dedicated `sample_count` for LOAD, `out_count` for UNLOAD  
**Rationale:**
- **Bug Found:** Reusing single counter caused UNLOAD state to hang because counter was already at 4096 when entering UNLOAD
- **Fix:** Independent counters ensure clean state transitions
- `sample_count` tracks input samples (0 to 4095)
- `out_count` tracks output samples (0 to 4095)

### Decision 2.4: AXI4-Stream Handshake Protocol
**Choice:** Strict compliance with tvalid/tready handshake rules  
**Rationale:**
- Master must hold `tvalid` high until `tready` is asserted
- Data must remain stable during handshake
- **Critical Bug Found:** Premature deassertion of `tvalid` caused FFT IP to miss final sample
- **Fix:** Hold `fft_in_valid` high throughout LOAD state, deassert only in subsequent state

### Decision 2.5: State Machine Design (IDLE → LOAD → UNLOAD)
**Choice:** Three-state FSM with explicit transitions  
**Rationale:**
- **IDLE:** Wait for `start` signal, clear all counters
- **LOAD:** Accept 4096 input samples, assert `tlast` on final sample
- **UNLOAD:** Output 4096 FFT results, rely on `m_axis_data_tlast` from IP
- **Critical Design Pattern:** Check termination condition BEFORE incrementing counter to avoid non-blocking assignment race conditions

```verilog
// CORRECT pattern (avoids NBA trap):
LOAD: begin
    if (in_valid && s_axis_data_tready) begin
        if (sample_count == FFT_SIZE - 1) begin  // Check FIRST
            state <= UNLOAD;
        end else begin
            sample_count <= sample_count + 1;    // Increment SECOND
        end
    end
end
```

## 🎯 3. Acquisition Engine State Machine Design

### Decision 3.1: Eight-State Control FSM
**Choice:** IDLE → WAIT_FIFO → WIPEOFF → LOAD_FWD → STREAM_MULT → LOAD_INV → WAIT_INV → DONE  
**Rationale:**
- Clear separation of concerns for each pipeline stage
- Enables precise control of FFT wrapper start/done signals
- Allows intermediate buffering between stages
- Facilitates debugging with state-specific monitors

### Decision 3.2: Local BRAM Buffers for Data Staging
**Choice:** Four 4096×18-bit BRAM arrays (`i_buf`, `q_buf`, `mult_i_buf`, `mult_q_buf`)  
**Rationale:**
- Decouples FIFO read timing from FFT input timing
- Allows carrier wipe-off to complete before FFT starts
- Stores complex multiplication results for IFFT input
- Total: 4 × 4096 × 18 bits = 36 KB = 1 BRAM36K per buffer

### Decision 3.3: Wait Flags for FFT Start Synchronization
**Choice:** `load_fwd_wait` and `load_inv_wait` flags  
**Rationale:**
- **Critical Bug Found:** FFT wrapper needs one cycle to transition from IDLE to LOAD after `start` is asserted
- Without wait flag, engine would start feeding data before wrapper is ready, causing first sample to be lost
- **Fix:** Assert `start` with `in_valid=0` for one cycle, then begin data transfer
```verilog
if (!load_fwd_wait) begin
    fft_start <= 1'b1;
    fft_in_valid <= 1'b0;  // Wait cycle
    load_fwd_wait <= 1'b1;
end else begin
    fft_start <= 1'b0;
    fft_in_valid <= 1'b1;  // Start data transfer
    // ... feed data ...
end

```verilog
  if (!load_fwd_wait) begin
      fft_start <= 1'b1;
      fft_in_valid <= 1'b0;  // Wait cycle
      load_fwd_wait <= 1'b1;
  end else begin
      fft_start <= 1'b0;
      fft_in_valid <= 1'b1;  // Start data transfer
      // ... feed data ...
  end
```

### Decision 3.4: Peak Detector Arming Timing
**Choice:** Assert `pd_start` at end of `LOAD_INV`, hold through `WAIT_INV`  
**Rationale:**
- **Critical Bug Found:** Peak detector was armed too late (in `WAIT_INV`), missing early IFFT output
- FFT output begins during `LOAD_INV` state, not `WAIT_INV`
- **Fix:** Assert `pd_start` when transitioning to `WAIT_INV`, deassert after one cycle
- Prevents peak detector from continuously resetting its counter

### Decision 3.5: Continuous Multiplier Enable During STREAM_MULT
**Choice:** Keep `mult_enable = 1` throughout `STREAM_MULT` state  
**Rationale:**
- **Critical Bug Found:** Gating multiplier with `fft_out_valid` caused pipeline stall
- Complex multiplier is pipelined; premature disable prevents final result from flushing
- **Fix:** Keep multiplier enabled continuously, let it process all 4096 samples
- Ensures all 4096 multiplication results are produced

## 📊 4. Peak Detector Design Decisions

### Decision 4.1: Magnitude Calculation Method
**Choice:** `mag = (I² + Q²) >>> 4` (36-bit sum, shift right by 4)  
**Rationale:**
- Computes power (magnitude squared) without expensive square root
- 18-bit × 18-bit = 36-bit product
- Sum of two 36-bit values = 37-bit result (with carry)
- Shift right by 4 scales to 32-bit output for comparison
- **Critical Bug Found:** Initial implementation used `>>> 16`, which truncated small values to zero
- **Fix:** Changed to `>>> 4` (or bit-slice `[35:4]`) to preserve precision

### Decision 4.2: Self-Arming on First Valid Data
**Choice:** Peak detector arms when `start` is asserted, begins counting on first `data_valid`  
**Rationale:**
- **Critical Bug Found:** `pd_start` held high too long caused continuous reset
- **Fix:** Deassert `pd_start` after one cycle in `WAIT_INV` state
- Peak detector uses state machine: `{armed, done} = {0,0} → {1,0} → {1,1}`
- Counts `data_valid` pulses from 0 to 4095, asserts `done` when complete

### Decision 4.3: Signed Arithmetic for Squaring
**Choice:** Use `$signed()` casting for I² and Q² computation  
**Rationale:**
- Ensures proper sign extension during multiplication
- Prevents incorrect results from unsigned interpretation of negative values
- Example: `(-5)² = 25`, not `65511` (if treated as unsigned 16-bit)

## 🧪 5. Testbench Design Decisions

### Decision 5.1: Absolute Path for `$readmemh`
**Choice:** Use full absolute paths for `.hex` files  
**Rationale:**
- XSim runs from hidden `.sim/sim_1/behav/xsim/` directory
- Relative paths fail because files are not in simulator working directory
- **Fix:** Use `/home/johan2/Documents/fpga/event-horizon-gnss/hardware/rtl/acquisition/` prefix
- Ensures simulator can locate ROM initialization files

### Decision 5.2: DC Bias Removal in Testbench
**Choice:** Subtract mean from stimulus before playback  
**Rationale:**
- **Critical Bug Found:** DC offset in stimulus created massive fake peak at code phase 0
- Bin 0 magnitude was 540,280 while other bins were < 1,000
- **Fix:** Calculate mean of all samples, subtract from each sample
```verilog
for (i = 0; i < FFT_SIZE; i = i + 1) begin
    sum_i = sum_i + $signed(stim_i_mem[i]);
    sum_q = sum_q + $signed(stim_q_mem[i]);
end
mean_i = sum_i / FFT_SIZE;
mean_q = sum_q / FFT_SIZE;
for (i = 0; i < FFT_SIZE; i = i + 1) begin
    stim_i_mem[i] = stim_i_mem[i] - mean_i;
    stim_q_mem[i] = stim_q_mem[i] - mean_q;
end
```

### Decision 5.3: Watchdog Timer for Stuck Detection
**Choice:** 500,000-cycle timeout with detailed state dump  
**Rationale:**
- Prevents infinite simulation hangs during debugging
- Monitors state changes and key signals (`fft_out_valid`, `pd_done`)
- Prints detailed diagnostics when timeout occurs:
  - Current state
  - FFT wrapper internal state
  - Sample counts
  - Signal values
- Enables rapid identification of stuck conditions

### Decision 5.4: Comprehensive Debug Probes
**Choice:** State transition monitors, FFT wrapper state monitors, peak detector counters  
**Rationale:**
- Visibility into internal module behavior without modifying DUT
- Tracks state machine transitions with timestamps
- Monitors FFT wrapper IDLE/LOAD/UNLOAD states
- Prints peak detector count, magnitude, and max values
- Essential for debugging complex multi-stage pipelines

## 🔄 6. Clock Domain Crossing Design

### Decision 6.1: Async FIFO Configuration
**Choice:** 8192-depth FIFO with independent read/write clocks  
**Rationale:**
- Provides sufficient buffering for clock frequency ratio (2:1)
- Prevents data loss during CDC transfer
- Uses Xilinx FIFO Generator IP for reliable implementation
- Status signals: `fifo_full`, `fifo_empty`, `fifo_data_valid`

### Decision 6.2: Reset Synchronization
**Choice:** Remove `wr_rst_busy`/`rd_rst_busy` from FIFO status logic  
**Rationale:**
- **Critical Bug Found:** Including busy signals caused `0 | z = x` propagation
- Xilinx FIFO behavioral model leaves busy signals high-impedance after reset
- **Fix:** Use only `fifo_full` and `fifo_empty` for status
- Prevents `x` propagation through control logic

## 💾 7. ROM and Memory Initialization

### Decision 7.1: Block RAM Inference for ROMs
**Choice:** Use `(* ram_style = "block" *)` attribute  
**Rationale:**
- Forces Vivado to infer BRAM instead of distributed LUT RAM
- Critical for large ROMs (e.g., 32 PRNs × 4096 bins = 131,072 entries)
- Saves thousands of LUTs
- Ensures predictable resource utilization

### Decision 7.2: Pre-computed Code FFT Storage
**Choice:** Store conjugated FFT of all 32 PRN codes in ROM  
**Rationale:**
- Eliminates need to compute code FFT at runtime
- Reduces acquisition latency
- Total storage: 32 × 4096 × 2 (I/Q) × 18 bits = 4.7 MB = ~32 BRAM36K
- Loaded from `.hex` files at elaboration time

### Decision 7.3: NCO ROM for Carrier Wipe-off
**Choice:** 4096-entry cos/sin lookup table  
**Rationale:**
- Provides fine frequency resolution for Doppler compensation
- 18-bit signed output matches data path width
- Indexed by top 12 bits of 48-bit phase accumulator
- Loaded from `nco_cos.hex` and `nco_sin.hex`

## 🐛 8. Critical Bugs and Resolutions

| Bug | Symptom | Root Cause | Fix |
|-----|---------|------------|-----|
| **8.1: Non-Blocking Assignment Race** | FFT wrapper stuck in LOAD, `sample_count` never reached 4095 | `sample_count <= sample_count + 1` followed by `if` checked old value | Check condition BEFORE incrementing counter |
| **8.2: Peak Detector Continuous Reset** | `sample_count` stuck at 0 in peak detector | `pd_start` held high throughout WAIT_INV state | Deassert `pd_start` after one cycle |
| **8.3: Final Sample Lost** | `pd_done` never asserted, 4096th sample not processed | `out_valid <= 1` overridden by `out_valid <= 0` in same cycle | Removed override, let state transition clear it naturally |
| **8.4: Magnitude Precision Loss** | `current_mag = 0` for non-zero inputs | `>>> 16` shift too aggressive for 18-bit inputs | Changed to `>>> 4` (or `[35:4]` bit-slice) |
| **8.5: DC Bias Creating Fake Peak** | Code phase always 0, magnitude abnormally high | Input stimulus had DC offset | Subtract mean from all samples in testbench |
| **8.6: Vivado Cache Ghosting** | Changes to source files not reflected in simulation | Vivado incremental compilation cache held stale data | `rm -rf event_horizon_acquisition.sim` + restart Vivado |

## 🎓 12. Key Lessons Learned

1. **Non-blocking assignments are tricky:** Always check conditions BEFORE incrementing counters in synchronous logic
2. **Vivado cache is aggressive:** When changes don't reflect, nuke `.sim` directory and restart Vivado
3. **DC bias is a silent killer:** Always remove DC offset before FFT-based correlation
4. **Timing matters:** Arm detectors BEFORE data arrives, not after
5. **Debug prints are invaluable:** `$display` statements in critical states save hours of debugging
6. **Serial architectures win on FPGAs:** Time-multiplexing is almost always better than parallel instantiation when resources are constrained
7. **AXI4-Stream protocol is strict:** Hold `tvalid` high until `tready`, keep data stable
8. **Xilinx IP configuration is critical:** Bit ordering matters; consult product guides carefully
