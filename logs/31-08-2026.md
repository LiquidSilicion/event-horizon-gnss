## 3. Phase 2: Acquisition Engine Research & Architecture
We conducted a deep-dive into optimized FPGA acquisition architectures, analyzing three key research papers:
1.  **Majoral et al. (Sensors 2023):** Validated the SoC-FPGA partitioning approach (Heavy DSP in PL, Loop Filters/Navigation in ARM PS via AXI4).
2.  **Leclère et al. (2015) - FFT Splitting:** Analyzed the 9-FFT (3-way) and 15-FFT (5-way) splitting techniques to reduce BRAM usage by up to 84% for larger FFT sizes.
3.  **Guruprasad (2015):** Confirmed the critical necessity of using **16-bit or 18-bit data paths**. Using 8-bit paths forces scaling/truncation, which destroys acquisition sensitivity and causes false locks.

### Architectural Decisions
*   **Algorithm:** Parallel Code Phase Search (PCPS) using FFT (from `gnss-sdr`).
*   **Sampling Rate:** Sticking to **4 MHz** (4096-point FFT) for now. This perfectly matches the tracking engine, requires no resampler, and fits easily in the Zynq-7020. (16 MHz upgrade path is documented for future multi-constellation support).
*   **Resource Budget:** The 4096-point design uses ~16 BRAMs and ~15 DSPs, leaving >80% of the Zynq-7020 fabric free for 12+ tracking channels.

## 5. Verilog RTL Implementation
We wrote the synthesizable Verilog modules for the acquisition engine, strictly adhering to Verilog-2001 standards and Xilinx best practices.

### 5.1. `fft_wrapper.v`
*   Wraps the Xilinx FFT IP Core.
*   Handles the AXI4-Stream handshaking (`tvalid`, `tready`, `tlast`).
*   Features an `inverse` control pin to seamlessly switch between Forward FFT (for input signal) and IFFT (for correlation output) using a single IP instance.

### 5.2. `code_fft_rom.v`
*   Stores the pre-computed complex-conjugated FFT of the local C/A codes.
*   **Crucial Synthesis Attribute:** Added `(* ram_style = "block" *)` above the array declarations to force Vivado to infer dedicated Block RAM (BRAM) instead of wasting thousands of LUTs on Distributed RAM.
*   Uses `$readmemh` with absolute paths to load the master hex files.

### 5.3. `complex_multiplier.v`
*   Implements the frequency-domain multiplication: `(FFT_Input) × (FFT_Code)*`.
*   **Optimization:** Uses the **3-Multiplier Gauss Optimization** (`k1 = a_i*b_i`, `k2 = a_q*b_q`, `k3 = (a_i+a_q)*(b_i+b_q)`) to reduce DSP48 slice usage by 25% compared to the standard 4-multiplier approach.

### 5.4. `magnitude_squared.v` (Peak Detector)
*   Computes $I^2 + Q^2$ to find the correlation peak.
*   **Fix Applied:** Replaced the standard `>> 16` right-shift operator with explicit bit-slicing (`mag_sum[47:16]`). This prevents Vivado from throwing signed/unsigned truncation warnings and guarantees a clean 32-bit positive magnitude output.

### 5.5. `acquisition_engine.v` (Top-Level State Machine)
Drafted the master FSM that orchestrates the PCPS algorithm:
`IDLE` ➔ `LOAD_SAMPLES` ➔ `CARRIER_WIPEOFF` ➔ `FFT_FWD` ➔ `MULTIPLY` ➔ `FFT_INV` ➔ `PEAK_DETECT` ➔ `NEXT_DOPPLER` ➔ `DONE`.

## 6. Xilinx FFT IP Core Configuration
For the upcoming synthesis, the Xilinx FFT IP must be configured exactly as follows to match our RTL and resource constraints:
| Parameter | Setting | Reason |
| :--- | :--- | :--- |
| **Transform Length** | `4096` | Matches 4 MHz sample rate, 1 ms integration |
| **Target Clock** | `100 MHz` (or `200 MHz` via PLL) | Matches system clock / doubles throughput |
| **Data Format** | `Fixed Point` | Standard for FPGA DSP |
| **Input/Output Width** | `18 bits` | Matches DSP48E1 native multiplier width |
| **Phase Factor Width** | `18 bits` | High accuracy twiddle factors |
| **Architecture** | `Radix-4 Burst I/O` | Best balance of BRAM savings and speed |
| **Scaling** | `Block Floating Point` | **Critical:** Prevents internal overflow without losing weak signals |
| **Complex Multipliers** | `Use 3-multiplier structure` | Saves 25% of DSP slices |
| **Butterfly Arithmetic**| `Use XtremeDSP slice` | Uses dedicated DSP48 adders, saves LUTs |
