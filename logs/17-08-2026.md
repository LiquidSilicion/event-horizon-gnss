## Hardware / Software Partition

### FPGA — Programmable Logic (high-throughput DSP)

| Block | Function |
|-------|----------|
| Signal ingestion | Stream raw I/Q samples via AXI-DMA, bypassing the CPU entirely |
| Conditioning | Digital down-conversion (DDC), filtering, resampling |
| Acquisition | FFT-based parallel correlators; brute-force search of Doppler × code-phase space |
| Tracking | Per-channel NCOs, carrier PLL, code DLL, early/prompt/late correlators |

Operates at the **sample rate** (MS/s). Deterministic, massively parallel, fixed-point.

### ARM — Processing System (low-rate, sequential)

| Block | Function |
|-------|----------|
| Telemetry decoding | Bit/frame synchronization, FEC decoding (Viterbi / BCH / LDPC) |
| PVT solution | Pseudorange computation, least-squares estimation, Kalman filtering |
| Control | Channel allocation, acquisition → tracking state machine |
| System | Linux OS, UIO drivers, logging, output interfaces |

Operates at the **symbol/epoch rate** (50 bps per satellite → 1–10 Hz PVT). Floating-point, sequential.

### PL ↔ PS Interface

- **AXI-Stream + DMA** — raw samples into the FPGA fabric.
- **AXI-Lite (memory-mapped registers)** — ARM configures FPGA parameters (Doppler bins, code phase, loop coefficients).
- **Shared memory + interrupts** — correlator outputs and decoded symbols handed to the ARM each epoch.

## Target Hardware Strategy

**Modeling / development:** ZedBoard (Zynq-7020)
**Final implementation:** Analog Devices ADRV9361-Z7035

| | ZedBoard (dev) | ADRV9361-Z7035 (final) |
|---|---|---|
| PS | Dual-core ARM Cortex-A9 | Dual-core ARM Cortex-A9 |
| PL class | Artix-7 equivalent (~85K LC, 220 DSP48) | Kintex-7 equivalent (~275K LC, 900 DSP48) |
| RF front-end | File captures → AD9361 FMC (AD-FMCOMMS) | Onboard AD9361 (70 MHz–6 GHz; L1/L2/L5) |
| Role | RTL development, DMA/AXI plumbing, SW stack | Full-rate, full-channel real-time receiver |

**Notes:**
- Same Zynq-7000 family → Linux BSP, device tree, UIO drivers, and `gnss-sdr` builds are portable across both boards.
- Developing inside the Z-7020 resource envelope enforces a strict budget; anything that fits on the 7020 fits on the 7035 with headroom for extra channels.
- RTL will be parameterized (`NUM_CHANNELS`, correlator parallelism, sample width) so a single codebase targets both parts; only the part number and XDC constraints change.
- Reuse Analog Devices' open HDL (`axi_ad9361`, `axi_dmac`) for the RF data path on both boards to keep the digital interface identical.
