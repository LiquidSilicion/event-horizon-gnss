## 2. Hardware Interface Diagnosis & Pivot

### 2.1 The JTAG Connectivity Issue
*   **Symptom:** Vivado Hardware Manager could not detect the `xc7z020` device via the micro-USB port; DONE LED remained off.
*   **Diagnosis:** `lsusb` identified the onboard USB bridge as `ID 04b4:0008 Cypress Semiconductor Corp. CDC ACM serial port` instead of the expected FTDI FT2232H (`0403:6010`).
*   **Root Cause:** This clone/lab variant uses a cheaper Cypress chip wired strictly for UART console access. It lacks the hardware MPSSE engine required by Vivado for JTAG boundary scan and FPGA configuration.
*   **Decision:** Bypass USB-JTAG entirely. Utilize the Zynq PS BootROM's native ability to load the Programmable Logic (PL) directly from an SD card at power-on.

### 2.2 Debug Probes Strategy
*   **Decision:** Retained `(* mark_debug = "true" *)` attributes in `tracking_top.v`.
*   **Rationale:** While ILA waveforms cannot be viewed without JTAG, retaining the debug cores validates that the ILA integration does not violate timing closure. The DONE LED serves as the primary functional indicator for today's session.

## 3. SD Card Boot Implementation (Vivado 2024.1 Workflow)

Since the legacy Vitis "Create Boot Image" GUI wizard is deprecated in 2024.1, we utilized the command-line `bootgen` utility.

### 3.1 Bitstream Preparation
1.  Verified timing closure: **WNS = +1.823 ns**, **WHS = +0.119 ns** @ 100 MHz.
2.  Located routed bitstream: `<project>.runs/impl_1/tracking_top.bit`.
3.  Copied `.bit` file to project root for simplified path management.

### 3.2 Boot Image Generation (`bootgen`)
Created `boot.bif` with a standalone PL partition (no FSBL required for pure fabric configuration):

```text
the_ROM_image:
{
    [destination_device=pl] /home/johan/event_horizon_gnss/tracking_top.bit
}
```

``Executed generated command:``

source /tools/Xilinx/Vivado/2024.1/settings64.sh
bootgen -image boot.bif -arch zynq -o BOOT.BIN -w


Result: BOOT.BIN generated successfully.

### 3.3 Physical Deployment
1. Formatted microSD card to **FAT32**.
2. Copied `BOOT.BIN` to the SD card root directory.
3. Configured ZedBoard Boot Mode Switches (**SW11**) to SD Boot:
   * **SW1:** ON (Up)
   * **SW2:** OFF (Down)
   * **SW3:** OFF (Down)
   * **SW4:** ON (Up)
   * **SW5:** OFF (Down)
   * *(Binary: 10010)*
