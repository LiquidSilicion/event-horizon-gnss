## ✅ Completed Tasks

### 1. Architecture Restructuring
- **Moved `doppler_search_controller` inside `acquisition_engine`**
  - Controller now drives `done`, `busy`, and final results directly
  - Local FSM triggers on `acq_start` (internal), not external `start`
  - Local FSM pulses `acq_done` back to controller when one acquisition completes
  - Testbench simplified to just pulse `start` once and wait for `done`
  - `acquisition_engine` is now a reusable, self-contained IP block

- **Instantiated `nci_accumulator` inside `acquisition_engine`**
  - 4096 × 32-bit BRAM-based accumulator array
  - Sequential clear mechanism (4096 cycles) to avoid multi-driver conflicts
  - `clear` input triggered by `acq_start` at the beginning of each Doppler bin
  - Parallel read interface for `ST_NCI_SCAN` state

### 2. NCI Accumulator Module (`nci_accumulator.v`)
- Created dedicated module with:
  - Magnitude computation: `(I² + Q²) >>> 8` (shift right by 8 to prevent overflow over 20 frames)
  - `clear` signal for memory wipe between Doppler bins
  - `clear_done` output to indicate when memory is fully zeroed
  - `accum_addr` and `clear_addr` as separate counters to prevent conflicts
  - `initial` block for clean simulation memory initialization

### 3. State Machine Updates (`acquisition_engine.v`)
- Added new states: `ST_NCI_SCAN` (4'd7) and `ST_DONE` (4'd8)
- Added `nci_count` register (5-bit, 0 to NCI_FRAMES-1)
- NCI loop in `ST_WAIT_INV`: loops back to `ST_WAIT_FIFO` until `nci_count == NCI_FRAMES - 1`
- `ST_NCI_SCAN`: sequentially reads all 4096 bins from NCI memory, compares with `acq_peak_mag`
- Removed standalone `peak_detector` module (scanning now handled natively in FSM)
- Added `acq_start_latched` register to wait for `nci_clear_done` before starting first frame

### 4. Doppler Controller Fix (`doppler_search_controller.v`)
- Fixed `acq_start` to pulse at the beginning of **every** Doppler bin (not just the first)
- This ensures the NCI accumulator clears its memory between bins
- Added `acq_start <= 1'b0` deassertion in `ST_START_ACQ` for clean 1-cycle pulse

### 5. Bug Fixes
| Bug | Root Cause | Fix |
|-----|-----------|-----|
| Duplicate wire declaration | `nci_fft_valid` declared twice | Removed duplicate, kept single declaration |
| NCI accumulating forward FFT | `fft_out_valid` fires for both forward and inverse FFT | Added `nci_fft_valid = fft_out_valid & fft_inverse` gating |
| NCI skipping bin 0 | `nci_read_addr` incremented before comparison | Changed order: compare first, then increment |
| NCI memory not cleared | Accumulator clear takes 4096 cycles, engine started immediately | Added `acq_start_latched` + `nci_clear_done` wait |
| NCI not clearing between bins | `acq_start` only pulsed once at search start | Controller now pulses `acq_start` for every bin |
| Verilog-2001 compilation error | Variables declared inside `for` loop | Moved all declarations to module level |

## 🐛 Outstanding Issues

### Issue: NCI Peak Magnitude Not Scaling
**Symptom:** Peak magnitude with 20ms NCI (661,318) is not 20× the 1ms baseline (1,007,496). Expected ~20,000,000+.

**Possible Root Causes Under Investigation:**
1. The `nci_fft_valid` gate (`fft_out_valid & fft_inverse`) may not be correctly isolating IFFT-only output
2. The `>>> 8` shift in the NCI accumulator may be causing excessive precision loss
3. The stimulus signal (`stim_i.hex` / `stim_q.hex`) may not contain a strong enough GPS signal to survive 20ms integration with the current scaling
4. The Xilinx FFT IP Block Floating Point (BFP) scaling may be normalizing differently across frames, making direct magnitude accumulation invalid

**Evidence from logs:**
- Per-frame peak detector shows `mag=519946` at bin 0 for most Doppler bins (noise floor)
- Bin 5 (0 Hz) shows `max_mag=1007496` (the true signal peak)
- Bin 5 (0 Hz) also shows `max_mag=526779` and `max_mag=550156` in other frames
- The per-frame peaks are correct, but the accumulated NCI values are wrong

## 🔬 Technical Notes

### NCI Accumulator Design Decisions
- **Scaling:** `>>> 8` shift applied to prevent 32-bit overflow over 20 frames
  - Max per-frame: `(2^17)² × 2 = 2^35`
  - After 20 frames: `20 × 2^35 / 2^8 = 2^31.3` (fits in 32-bit)
  - Trade-off: loses 8 bits of precision per sample
- **Clear mechanism:** Sequential (4096 cycles = 20.48 µs at 200 MHz)
- **Read interface:** Combinational (BRAM read), always valid

### 2D Search Timing
| Metric | Value |
|--------|-------|
| Time per frame (pipeline) | ~198 µs simulated |
| Frames per Doppler bin | 20 (configurable) |
| Time per Doppler bin | 20 × 198 µs = ~4 ms |
| Total for 11 bins | ~44 ms simulated |
| Wall-clock time (XSim) | ~25-30 minutes |
| Hardware time (FPGA) | ~231 ms |

### Xilinx FFT IP Configuration
- Mode: Radix-4 Burst I/O
- Scaling: Block Floating Point (BFP)
- Data Width: 18-bit input
- Latency: ~15 µs for 4096-point @ 200 MHz
- **Important:** BFP scaling may affect NCI accumulation validity across frames

## 💡 Key Learnings

1. **Self-contained IP design** makes modules reusable and testbenches simpler
2. **FFT output gating** is critical when sharing a single FFT IP between forward and inverse transforms
3. **BRAM clearing** must complete before new data arrives; use handshake signals (`clear_done`)
4. **Sequential scan** in NCI must compare before incrementing to avoid skipping index 0
5. **Block Floating Point** FFT scaling may invalidate direct magnitude accumulation across frames — requires investigation
6. **XSim simulation time** scales linearly with total pipeline runs (11 bins × 20 frames = 220 runs)
