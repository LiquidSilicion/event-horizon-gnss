## 1. Executive Summary
Today's session was dedicated to the rigorous RTL integration and behavioral simulation of the FFT-based acquisition engine. While the architectural decisions finalized on August 31st provided a solid foundation, integrating the Xilinx IP cores, managing Clock Domain Crossing (CDC), and handling raw RF stimulus data revealed several critical low-level protocol and formatting bugs. 

Through systematic debugging, we resolved fatal AXI4-Stream handshaking deadlocks, corrected a severe bit-ordering error in the Xilinx FFT IP configuration vector, and established a robust Verilog-2001 compliant testbench environment. The acquisition pipeline is now fully unblocked and successfully processes real captured GPS data through the Forward FFT, Complex Multiplication, and Inverse FFT stages.

## 2. Validation of Architectural Decisions (Ref: Aug 31 Log)
Today's debugging heavily validated the core architectural decisions documented in the `decision-31-08-2026.md` knowledge base:
* **Decision 4.1 (18-bit Signed Data Path):** Maintaining 18-bit widths prevented the truncation errors warned about in Guruprasad (2015). The 48-bit AXI4-Stream padding `{6'b0, 18-bit I}, {6'b0, 18-bit Q}` mapped perfectly to the Xilinx FFT IP without data loss.
* **Decision 4.3 (100 MHz → 200 MHz CDC):** The Native Independent Clock Built-In FIFO successfully bridged the ADC sample domain to the processing domain. 
* **Decision 4.4 (Sequential State Machine with BRAM Buffers):** Using intermediate BRAM buffers (`i_buf`, `q_buf`, `mult_i_buf`) instead of pure streaming prevented catastrophic handshaking deadlocks with the Xilinx FFT IP's internal state machine, proving this was the correct architectural choice for debuggability and timing closure.

## 3. Critical RTL & Simulation Resolutions

### 3.1 FIFO CDC Bridge & Reset Synchronization
* **Issue:** The AXI4-Stream FIFO exhibited `x` and `z` propagation on `fifo_full` and `data_valid` during behavioral simulation, causing the state machine to hang in `ST_WAIT_FIFO`.
* **Resolution:** Transitioned from an AXI4-Stream FIFO to a **Native Independent Clock Built-In FIFO**. Removed dependencies on `wr_rst_busy` and `rd_rst_busy` (which are high-impedance `z` in behavioral models). Implemented strict `rd_en` gating driven by the state machine to prevent premature FIFO draining.

### 3.2 Raw RF Stimulus Data Formatting
* **Issue:** Testbench fed garbage data (repeating `0x80FF` / -32513) into the engine, resulting in a peak magnitude of 0.
* **Root Cause:** The raw binary GPS capture (`GPS_L1_4FS_0IF_0dB_test1.bin`) was formatted as 8-bit interleaved I/Q data, but the initial Python parsing script assumed 16-bit integers.
* **Resolution:** Developed a diagnostic Python script to correctly parse the 8-bit signed data, scale it to 16-bit signed integers, and export cleanly to `stim_i.hex` and `stim_q.hex`. 

### 3.3 Verilog-2001 Testbench Strictness
* **Issue:** Vivado's strict Verilog-2001 compiler rejected SystemVerilog constructs (`string` types, inline `integer` declarations, missing `begin/end` blocks in tasks).
* **Resolution:** Refactored `tb_acquisition_engine.v` to move all `integer` and `reg` declarations to the module level. Hardcoded absolute file paths in `$fopen` tasks to bypass XSim's hidden working directory issues.

### 3.4 AXI4-Stream Master Handshake Deadlock
* **Issue:** The state machine permanently stalled in `ST_LOAD_FWD` and `ST_LOAD_INV`. The `sample_cnt` failed to reach 4095.
* **Root Cause:** A violation of the AXI4-Stream protocol. The master (`acquisition_engine`) was prematurely deasserting `fft_in_valid` (`tvalid`) on the exact clock cycle the slave (`fft_wrapper`) asserted `fft_in_ready` (`tready`) for the final sample. 
* **Resolution:** Modified the state machine to hold `fft_in_valid <= 1'b1` continuously throughout the `LOAD` states. The signal is now safely deasserted only upon entering the *subsequent* state (`ST_STREAM_MULT` or `ST_WAIT_INV`).

### 3.5 Xilinx FFT IP Configuration Vector (The "Smoking Gun")
* **Issue:** Despite receiving 4096 valid samples, the Xilinx FFT IP silently stalled and never asserted `m_axis_data_tvalid`, leaving `ST_STREAM_MULT` waiting indefinitely.
* **Root Cause:** A fatal bit-ordering error in the 8-bit configuration vector. The previous code `{2'b00, 1'b0, inverse, 4'd12}` placed the `NFFT` value in the least significant bits. The IP interpreted this as an invalid transform length and aborted processing.
* **Resolution:** Corrected the vector to strictly match the **Xilinx FFT v9.1 Product Guide (PG109)** for Radix-4 Burst I/O:
  ```verilog
  // Bits [7:4]: NFFT (12 = 4096 points)
  // Bits [3:1]: CP_LEN (000 = No Cyclic Prefix)
  // Bit 0:      FWD_INV (0 = Forward, 1 = Inverse)
  wire [7:0] config_tdata = {4'd12, 3'b000, inverse};

**Action Taken:** Forced a complete overwrite of `fft_wrapper.v` via terminal and cleared the Vivado `xsim.dir` cache to eliminate stale compilation artifacts.

## 3. Alignment with Knowledge Base (Aug 31, 2026)

Today's debugging and final fixes directly validated and enforced the core architectural decisions documented in the project log:

* **Decision 3.2 (FFT IP Core Configuration):** Successfully implemented Radix-4 Burst I/O architecture. The fix ensures the IP operates as intended, paving the way for Block Floating Point scaling to prevent overflow without losing weak signals.
* **Decision 4.1 (18-bit Signed Data Path):** Maintained throughout the engine. The 48-bit AXI4-Stream padding (`{6'b0, i_in}, {6'b0, q_in}`) correctly maps the 18-bit data to the DSP48E1 native multiplier width, preventing the accuracy loss documented in Guruprasad (2015).
* **Decision 4.3 (Clock Domain Crossing):** The 100 MHz → 200 MHz Async FIFO bridge is now functioning correctly, safely transferring data without `x`/`z` corruption.
* **Decision 4.4 (Sequential State Machine with BRAM Buffers):** The intermediate buffering (`i_buf`, `q_buf`, `mult_i_buf`) successfully prevented complex streaming handshaking deadlocks once the AXI4-Stream `tvalid`/`tready` rules were properly respected.
