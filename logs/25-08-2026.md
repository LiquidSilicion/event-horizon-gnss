## 2. Key Challenges & Resolutions

### 2.1 USB-JTAG / UART Identification
*   **Issue:** Vivado Hardware Manager failed to detect the ZedBoard via the micro-USB port. `lsusb` revealed a `Cypress Semiconductor Corp. CDC ACM` device instead of the standard FTDI chip.
*   **Resolution:** Identified the board as a university clone variant. The Cypress chip functions strictly as a USB-to-UART bridge (registering as `/dev/ttyACM0` in Linux), not a JTAG programmer. We successfully bypassed this by utilizing the physical 14-pin JTAG header (J13) with an external programmer, while using `/dev/ttyACM0` for serial console monitoring.

### 2.2 SD Card Boot & FSBL Generation
*   **Issue:** Initial attempts to boot a raw `.bit` file from the SD card failed because the Zynq-7000 Boot ROM requires an executable First Stage Boot Loader (FSBL) to initialize the PS and configure the PL.
*   **Resolution:** 
    1. Exported hardware to an `.xsa` file in Vivado 2025.2.
    2. Created a Platform Project and a Zynq FSBL Application in Vitis.
    3. Generated `BOOT.BIN` using the command-line `bootgen` tool:
       ```bash
       bootgen -image boot.bif -arch zynq -o BOOT.BIN -w on
       ```
    4. Configured boot jumpers (JP8, JP9, JP10) to `1-1-0` (SD Card mode) and shorted JP6 (SD level shifter enable).

### 2.3 XDC Constraint & I/O Overutilization
*   **Issue:** Implementation failed with `[Place 30-415] IO Placement failed due to overutilization. This design contains 361 I/O ports`. Additionally, timing failed due to a missing clock constraint.
*   **Resolution:** 
    *   Discovered internal tracking signals (e.g., `I_P`, `Q_P`, `phase_acc`) were accidentally declared as `input`/`output` instead of `wire`/`reg` in `tracking_top.v`. Corrected the module port list to expose *only* `clk_100mhz`, `rst_n`, `led_dump_valid`, and `led_tracking_ok`.
    *   Added the missing clock constraint: `create_clock -period 10.000 -name sys_clk [get_ports clk_100mhz]`.
    *   Corrected the reset pin from P17 to **P16 (BTNC)**, noting that ZedBoard buttons are **Active-High**. Implemented a logic inversion (`wire rst_n_internal = ~rst_n;`) in the RTL to maintain standard active-low reset semantics.

### 2.4 ILA Block RAM (BRAM) Overutilization
*   **Issue:** Adding the ILA caused synthesis to fail with `[Synth 8-5833] Design has more instantiated block-RAMs than device capacity`. 
*   **Root Cause:** An ILA depth of 65,536 with 114 total probe bits required ~7.4 Megabits of memory, exceeding the Zynq-7020's total physical capacity of 5.1 Megabits (140 BRAMs).
*   **Resolution:** 
    *   Reduced ILA **Data Depth to 1024**.
    *   Disabled `TRIGIN` and `TRIGOUT` in the ILA IP customization to save routing resources.
    *   Implemented **Advanced Triggering**: Configured the ILA to trigger *only* when `dump_valid_int == 1`. This allows us to capture a high-resolution, 10.24 µs "zoomed-in" window of the exact moment the 1 ms epoch completes, using only ~12 BRAMs.

## 3. Architectural Decisions & Configurations

### 3.1 Reset Polarity Handling
*   **Decision:** Invert the physical Active-High button (P16) to an Active-Low internal signal.
*   **Rationale:** Maintains industry-standard synchronous reset design practices (`if (!rst_n_internal)`) while accommodating the ZedBoard's hardware pull-down resistor design.

### 3.2 ILA Probe Q-Format Definitions
To ensure correct interpretation of the captured waveforms in the Vivado Hardware Manager, the following fixed-point formats were established for the 5 active ILA probes:

| Probe Signal | Bit Width | Q-Format | Purpose |
| :--- | :---: | :--- | :--- |
| `I_P_int`, `Q_P_int` | 32 | **Q16.16** | Prompt correlator outputs (Range: ±32,768, Res: ~0.000015) |
| `carrier_phase_int` | 48 | **Q48.0** | Carrier NCO phase accumulator (Sub-millimeter RTK resolution) |
| `dump_valid_int` | 1 | **Boolean** | 1 ms epoch completion pulse (1-clock-cycle wide) |
| `rst_n` | 1 | **Boolean** | System reset status (Used as secondary trigger condition) |

### 3.3 Debug Strategy: Trigger over Depth
*   **Decision:** Use a shallow ILA depth (1024) with a strict value trigger (`dump_valid_int == 1`) instead of a deep continuous capture.
*   **Rationale:** A 1 ms epoch at 100 MHz requires 100,000 samples. Capturing this continuously is physically impossible on a Zynq-7020. Triggering on the epoch boundary guarantees we capture the exact moment the correlator dumps its accumulated `I_P`/`Q_P` values, providing maximum debug value with minimal BRAM overhead.
