## 🐛 Critical Bugs Resolved Today

### Bug #1: Non-Blocking Assignment Trap in `fft_wrapper.v`
**Symptom:** FFT wrapper stuck in LOAD state, `sample_count` never reached 4095.  
**Root Cause:** In the LOAD state, `sample_count <= sample_count + 1` was followed by `if (sample_count == FFT_SIZE - 1)` — but the `if` checked the **old value** due to non-blocking assignment semantics.  
**Fix:** Separated counting from transition check into two independent `if` statements that run every cycle.

### Bug #2: `pd_start` Held High Too Long
**Symptom:** Peak detector's `sample_count` stuck at 0, never incremented.  
**Root Cause:** `pd_start` remained high throughout `ST_WAIT_INV`, causing the peak detector to reset its counter every cycle.  
**Fix:** Deassert `pd_start` immediately after one cycle in `ST_WAIT_INV`.

### Bug #3: `out_valid` Override on Final Sample
**Symptom:** 4096th sample lost, `pd_done` never asserted.  
**Root Cause:** In `UNLOAD` state, `out_valid <= 1` was immediately overridden by `out_valid <= 0` on the last cycle.  
**Fix:** Removed the override; let `out_valid` naturally clear when state transitions to IDLE.

### Bug #4: Peak Detector Armed Too Late
**Symptom:** FFT output missed by peak detector during IFFT phase.  
**Root Cause:** `pd_start` pulsed when transitioning to `ST_WAIT_INV`, but FFT output began during `ST_LOAD_INV`.  
**Fix:** Assert `pd_start` at the end of `ST_LOAD_INV` and hold through `ST_WAIT_INV`.

### Bug #5: Magnitude Calculation Precision Loss
**Symptom:** `current_mag = 0` even with non-zero I/Q inputs.  
**Root Cause:** `>>> 16` shift was too aggressive for 18-bit inputs (e.g., 890 >>> 16 = 0).  
**Fix:** Changed to `mag_sum[35:4]` bit-slicing (equivalent to `>>> 4`).

### Bug #6: DC Bias Creating Fake Peak at Bin 0
**Symptom:** Code phase always 0, magnitude 540,280 (abnormally high).  
**Root Cause:** Input stimulus had DC offset, creating massive energy at FFT bin 0.  
**Fix (Testbench):** Added DC removal by subtracting mean from all samples before playback.

### Bug #7: Vivado Cache Ghosting
**Symptom:** Changes to `fft_wrapper.v` not reflected in simulation despite file being correct.  
**Root Cause:** Vivado's incremental compilation cache held stale elaboration data.  
**Fix:** `rm -rf event_horizon_acquisition.sim` + restart Vivado.

## 🏗️ Architecture Implemented

### Final Working Pipeline

[ADC Input] → [CDC FIFO (100MHz → 200MHz)]
↓
[Carrier Wipe-Off (NCO + Complex Multiplier)]
↓
[Forward FFT (4096-pt, Radix-4, BFP)]
↓
[Complex Multiply (Code FFT Conjugate)]
↓
[Inverse FFT (4096-pt, Radix-4, BFP)]
↓
[Magnitude Squared + Peak Detection]
↓
[Output: best_code_phase, peak_magnitude]


### State Machine (8 States)
| State | Function |
|-------|----------|
| `ST_IDLE` | Wait for `start` signal |
| `ST_WAIT_FIFO` | Wait for FIFO to have data |
| `ST_WIPEOFF` | Carrier wipe-off + store to `i_buf`/`q_buf` |
| `ST_LOAD_FWD` | Load forward FFT with 4096 samples |
| `ST_STREAM_MULT` | Multiply FFT output × code FFT conjugate |
| `ST_LOAD_INV` | Load inverse FFT with 4096 multiplied samples |
| `ST_WAIT_INV` | Wait for IFFT output + peak detection |
| `ST_DONE` | Output results, return to IDLE |

## 📝 Key Technical Decisions

### Decision 1: Serial vs. Parallel Doppler Search
**Choice:** Serial (time-multiplexed)  
**Rationale:** 11 parallel FFT IPs would require ~176 BRAM36K (2.5× device capacity). Serial approach reuses single FFT IP, costs zero additional BRAM, only adds time.

### Decision 2: Non-Coherent Integration Depth
**Choice:** 20ms (20 × 1ms blocks)  
**Rationale:** Matches C code's `T_ACQ = 0.02`. Provides ~13 dB sensitivity improvement over 1ms. Avoids bit-transition issues by aligning to 1ms boundaries.

### Decision 3: CFAR vs. Fixed Threshold
**Choice:** CFAR (Constant False Alarm Rate)  
**Rationale:** Fixed threshold fails under varying RF conditions (jamming, urban canyons). CFAR adapts to noise floor, maintains constant false alarm probability.

### Decision 4: Parabolic Interpolation
**Choice:** 3-point parabolic fit  
**Rationale:** Provides sub-bin resolution (~0.1 chip accuracy) with minimal hardware (4 DSP48s). Critical for accurate pseudorange measurement.

## 🎓 Lessons Learned

1. **Non-blocking assignments are tricky:** Always check conditions **before** incrementing counters in synchronous logic.
2. **Vivado cache is aggressive:** When changes don't reflect, nuke `.sim` directory and restart Vivado.
3. **DC bias is a silent killer:** Always remove DC offset before FFT-based correlation.
4. **Timing matters:** Arm detectors **before** data arrives, not after.
5. **Debug prints are invaluable:** `$display` statements in critical states saved hours of debugging.
6. **Serial architectures win on FPGAs:** Time-multiplexing is almost always better than parallel instantiation when resources are constrained.
