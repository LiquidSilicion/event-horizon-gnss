## 📋 Executive Summary
Over the course of development, the GNSS acquisition engine has been transformed from a basic single-frame, single-PRN search block into a **production-grade, fully autonomous cold-start acquisition IP**. The design now supports Multi-PRN searching, Two-Stage Doppler refinement, 20ms Non-Coherent Integration (NCI) for ~13 dB sensitivity gain, and sub-chip parabolic interpolation for high-precision code phase estimation, all while maintaining strict resource efficiency on the Zynq-7020.

---

## 🏆 Key Milestones & Features Implemented

### 1. Non-Coherent Integration (NCI)
- **Module Created:** `nci_accumulator.v`
- **Functionality:** Accumulates magnitude-squared correlation results over multiple frames (configurable up to 20ms for GPS L1 C/A).
- **Optimization:** Implemented sequential BRAM clearing (4096 cycles) with a `clear_done` handshake to prevent data corruption between Doppler bins without requiring multi-port BRAMs.
- **Result:** Peak magnitude scaled from ~1M (1ms) to ~10.5M (20ms), proving correct accumulation without overflow (using `>>> 8` bit-shift scaling).

### 2. Architectural Encapsulation
- **Refactoring:** Moved `doppler_search_controller` *inside* `acquisition_engine.v`.
- **Benefit:** Transformed the design into a self-contained "black box" IP. The external interface is now simplified to a single `start` pulse and a `done` interrupt, making it trivial to instantiate multiple channels or interface with an ARM processor.

### 3. Sub-Chip Parabolic Interpolation
- **Module Created:** `parabolic_interpolator.v`
- **Mathematical Model:** Fits a parabola to the peak bin ($k$) and its neighbors ($k-1$, $k+1$) to estimate the true fractional code phase offset.
- **Hardware Optimization:** Replaced the unsynthesizable/slow hardware divider with a **Reciprocal LUT + DSP48 Multiplier** pipeline.
  - *Cycle 1:* Priority encoder normalizes the denominator to 8 bits.
  - *Cycle 2:* Synchronous Block RAM read of the pre-calculated reciprocal.
  - *Cycle 3:* DSP48 multiplication and fractional bit extraction.
- **Result:** Achieves ~0.004 chip resolution (1/256 chips) with only ~20 LUTs, 1 BRAM, and 1 DSP slice, adding only 3 clock cycles of latency.

### 4. Multi-PRN & Two-Stage Doppler Search
- **Module Updated:** `doppler_search_controller.v`
- **Functionality:** 
  - **Outer Loop:** Autonomously iterates through PRN 1 to 32.
  - **Stage 1 (Coarse):** Searches 11 bins at 1000 Hz steps.
  - **Stage 2 (Fine):** Centers a 5-bin (or 21-bin) search at 50 Hz steps around the coarse peak.
- **Result:** Enables a true "Cold Start" sky search without any testbench or CPU intervention.

## 🐛 Critical Bugs Encountered & Resolved

| Issue | Root Cause | Resolution |
| :--- | :--- | :--- |
| **NCI Accumulator Corruption** | State machine started accumulating before BRAM clearing finished. | Added `clear_done` output to `nci_accumulator` and a wait state in the main FSM. |
| **Duplicate Wire Declarations** | `nci_fft_valid` and `frac_offset` declared multiple times. | Consolidated declarations to the top of the module; used explicit `assign` statements. |
| **Incorrect Interpolation Inputs** | `prev_peak_mag` tracked the *previous peak*, not the adjacent bin $k-1$. | Rewrote scan logic to explicitly track `prev_bin_mag` and `last_bin_mag` for circular wrap-around. |
| **Edge-Case Skipping** | Interpolation skipped if peak was at bin 0 or 4095. | Implemented circular wrap-around logic (bin 0's $k-1$ is bin 4095). |
| **LUT Size Mismatch** | `reciprocal_lut.mem` had 256 entries, but logic expected 128. | Regenerated LUT via Python script to strictly output indices 128–255. |
| **Ghost Simulation Results** | Vivado cached old elaboration snapshots. | Enforced `rm -rf .../xsim` cache clearing before all major re-runs. |

## 💡 Key Engineering Takeaways
1. **Hardware Division is a Trap:** The Reciprocal LUT + DSP approach proved vastly superior to sequential dividers for GNSS interpolation, saving both time and resources.
2. **Simulation vs. Reality:** A 5.5-day simulation run translates to under 3 minutes on actual FPGA hardware. Smart parameter scaling (e.g., `NUM_PRNS=3`) is essential for agile RTL development.
3. **Edge Cases Matter:** Circular wrap-around for bin 0/4095 in the NCI scan was a subtle but critical fix for robust, real-world signal acquisition.
