## 2. Implementation & Debugging Decisions

### Decision 1.1: FIFO CDC Bridge — Remove Reset Busy Logic
**Decision:** Remove `wr_rst_busy` and `rd_rst_busy` signals from the `fifo_full` and `fifo_empty` assignments in `fft_fifo_bridge.v`.

**Rationale:**
- The Xilinx FIFO Generator behavioral model leaves `wr_rst_busy`/`rd_rst_busy` as high-impedance (`z`) after reset synchronization completes.
- Including these signals in the logic (`fifo_full = ~fifo_tready | wr_rst_busy`) caused `0 | z = x` propagation, corrupting the handshake signals.
- The FIFO's internal reset synchronization is complete once `fifo_tready` goes high, making external busy signals redundant for functional correctness.

**Reference:** Xilinx FIFO Generator User Guide (UG575), Section on Behavioral Model Limitations.

---

### Decision 1.2: Verilog-2001 Strict Compliance for Testbenches
**Decision:** Move all `integer` and `reg` variable declarations to the module level; replace dynamic `string` file paths with hardcoded absolute paths in `$fopen` tasks.

**Rationale:**
- Vivado's XSim compiler enforces strict Verilog-2001 rules, which do not allow:
  - Variable declarations inside unnamed `begin...end` blocks (e.g., `initial begin`).
  - `string` data types (a SystemVerilog feature).
- Moving declarations to module level and using hardcoded paths ensures 100% compatibility with the Verilog-2001 compiler.
- Absolute paths prevent file-not-found errors when XSim runs from its hidden `.sim/sim_1/behav/xsim/` directory.

### Decision 1.3: Stimulus Data Format — 8-bit to 16-bit Scaling
**Decision:** Parse the raw 8-bit signed GPS capture file (`GPS_L1_4FS_0IF_0dB_test1.bin`), scale to 16-bit signed integers, and generate `stim_i.hex` and `stim_q.hex`.

**Rationale:**
- The raw binary file contained 8-bit signed I/Q samples (range: -128 to 127).
- The acquisition engine expects 16-bit signed input (matching the 18-bit internal data path with 2-bit sign extension).
- Without scaling, the 8-bit values were being misinterpreted as 16-bit, producing garbage data (e.g., repeating `0x80FF` = -32513).
- Scaling by 256× (`i_scaled = i_8bit * 256`) maps the 8-bit range to the full 16-bit range, maximizing dynamic range utilization.

### Decision 1.4: AXI4-Stream Protocol — Hold tvalid Until tready
**Decision:** In `acquisition_engine.v`, hold `fft_in_valid` high continuously throughout the `ST_LOAD_FWD` and `ST_LOAD_INV` states; only deassert it in the subsequent state (`ST_STREAM_MULT` / `ST_WAIT_INV`).

**Rationale:**
- The AXI4-Stream protocol requires the master to keep `tvalid` high and data stable until the slave asserts `tready` on the same clock cycle.
- The previous code prematurely deasserted `fft_in_valid` on the final sample cycle (`sample_cnt == FFT_SIZE - 1`), causing the FFT wrapper to miss the 4096th sample.
- This left the FFT wrapper's internal counter at 4095 instead of 4096, preventing the transition from `LOAD` to `UNLOAD` state.
- By holding `fft_in_valid` high until the state transition, we guarantee the FFT wrapper receives all 4096 samples and correctly asserts `done`.

**Code Fix:**
```verilog
ST_LOAD_FWD: begin
    fft_in_valid <= 1'b1; // Hold high throughout this state
    fft_i_in <= i_buf[sample_cnt];
    fft_q_in <= q_buf[sample_cnt];
    
    if (fft_in_ready) begin
        if (sample_cnt == FFT_SIZE - 1) begin
            state <= ST_STREAM_MULT; // Deassert in next state
            sample_cnt <= 0;
        end else begin
            sample_cnt <= sample_cnt + 1;
        end
    end
end

ST_STREAM_MULT: begin
    fft_in_valid <= 1'b0; // Safely deasserted here
    // ... rest of state logic
end
