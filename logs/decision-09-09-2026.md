# GNSS Acquisition Engine - Design Decisions Summary

## 1. Non-Coherent Integration (NCI) Duration: 20ms

**Decision:** Set `NCI_FRAMES = 20` for 20ms of non-coherent integration

**Explanation:**
- GPS L1 C/A navigation data bits are 20ms long (50 bps data rate)
- 20ms NCI provides optimal sensitivity gain (~13 dB improvement over 1ms)
- Avoids bit boundary crossing issues that would cause signal cancellation
- Provides sufficient integration time to detect weak satellite signals
- Balances sensitivity with acquisition time (20ms per Doppler bin is acceptable)

**Trade-off:** Longer integration = better sensitivity but slower acquisition. 20ms is the sweet spot for GPS L1 C/A.

---

## 2. Doppler Search Strategy: Sequential Bin-by-Bin

**Decision:** Search Doppler bins sequentially (Bin 0, 1, 2, ... 17+) with 1000 Hz spacing

**Explanation:**
- GPS L1 C/A Doppler range: typically ±10 kHz (due to satellite motion + oscillator errors)
- 1000 Hz spacing matches the code search resolution (1 ms coherent integration = 1/(1ms) = 1000 Hz Doppler resolution)
- Sequential search is simpler than parallel search and uses less hardware resources
- Each bin requires full 20ms NCI integration before moving to next bin
- Frequency word progression: `000000000000` → `001355475a11` → `0013a92a3034` → ... (incrementing by ~1000 Hz steps)

**Trade-off:** Sequential search is slower than parallel but more resource-efficient. Acceptable for initial acquisition.

---

## 3. State Machine Architecture: 10-State Pipeline

**Decision:** Implement a 10-state FSM: IDLE → WAIT_FIFO → WIPEOFF → LOAD_FWD → STREAM_MULT → LOAD_INV → WAIT_INV → NCI_SCAN → INTERP → DONE

**Explanation:**
- **IDLE:** Wait for acquisition trigger
- **WAIT_FIFO:** Wait for FIFO to have 4096 samples (1ms of data)
- **WIPEOFF:** Carrier wipeoff (mix with NCO to remove carrier frequency)
- **LOAD_FWD:** Load data into FFT for forward FFT
- **STREAM_MULT:** Stream FFT output and multiply with code FFT (correlation)
- **LOAD_INV:** Load correlation result for inverse FFT
- **WAIT_INV:** Wait for IFFT to complete
- **NCI_SCAN:** Accumulate magnitude squared across NCI frames, find peak
- **INTERP:** Perform parabolic interpolation around peak for sub-chip resolution
- **DONE:** Signal acquisition complete

**Trade-off:** More states = more complex control logic, but each state is simple and uses minimal resources. Clear separation of concerns.

---

## 4. FFT-Based Parallel Code Phase Search

**Decision:** Use FFT to perform parallel correlation across all 4096 code phases simultaneously

**Explanation:**
- Traditional serial correlator: test one code phase at a time (4096 iterations)
- FFT-based correlator: FFT(signal) × FFT(code)* → IFFT = correlation at all 4096 phases
- Massive speedup: 4096 code phases tested in parallel in ~4096 clock cycles
- Requires storing code FFT in ROM (pre-computed)
- Uses Xilinx FFT IP core (4096-point, 18-bit data width)

**Trade-off:** Requires more BRAM (for code FFT storage) but dramatically faster than serial correlation. Essential for real-time acquisition.

---

## 5. Parabolic Interpolation for Sub-Chip Resolution

**Decision:** Implement parabolic interpolation in `ST_INTERP` state to refine code phase estimate

**Explanation:**
- FFT output gives code phase resolution of 1 chip (4096 chips / 4096 FFT bins)
- Parabolic interpolation fits a parabola to 3 adjacent bins (peak-1, peak, peak+1)
- Achieves sub-chip resolution (~0.01 chip accuracy)
- Critical for precise code phase estimation needed by tracking loops
- Implemented using DSP48 multipliers and LUT-based reciprocal calculation

**Trade-off:** Adds complexity and latency (~3 clock cycles) but provides essential precision improvement.

---

## 6. Frequency Word Progression Pattern

**Decision:** Increment frequency word by fixed step for each Doppler bin

**Explanation:**
- Observed pattern in log: `000000000000` → `001355475a11` → `0013a92a3034` → ...
- Each step represents ~1000 Hz Doppler shift
- Frequency word is 48-bit NCO control word: `freq_word = (freq_hz / clk_freq) × 2^48`
- For 100 MHz clock and 1000 Hz step: `step = (1000 / 100e6) × 2^48 ≈ 0x000053E2D623`
- Controller increments frequency word by this step for each bin

**Trade-off:** Fixed-step search is simple but may miss signals between bins. Acceptable for acquisition; tracking will refine further.

---

## 7. Complex Multiplication for Correlation

**Decision:** Use complex multiplier to multiply signal FFT with conjugate of code FFT

**Explanation:**
- Correlation theorem: `corr(a,b) = IFFT(FFT(a) × FFT(b)*)`
- Complex multiplier performs: `(I1 + jQ1) × (I2 - jQ2)`
- Implements: `I_out = I1×I2 + Q1×Q2`, `Q_out = Q1×I2 - I1×Q2`
- Uses 4 real multipliers or 3 multipliers with optimized architecture
- Xilinx Complex Multiplier IP core used for efficiency

**Trade-off:** Complex multiplication is resource-intensive but essential for frequency-domain correlation.

---

## 8. FIFO Buffering for Data Flow Management

**Decision:** Use 8192-sample FIFO between data input and FFT processing

**Explanation:**
- Decouples data acquisition rate from processing rate
- Allows continuous data collection while FFT processes previous batch
- Prevents data loss during FFT processing latency
- 8192 samples = 2ms of buffering at 4.096 MHz sampling rate
- Provides margin for FFT processing delays

**Trade-off:** Uses BRAM resources but ensures reliable data flow and prevents overflow.

---

## 9. Carrier Wipeoff Before FFT

**Decision:** Perform carrier wipeoff (NCO mixing) before FFT, not after

**Explanation:**
- Wipeoff removes carrier frequency offset, centering signal at baseband
- If done after FFT, would require frequency-domain shifting (more complex)
- Baseband signal has better FFT characteristics (less spectral leakage)
- NCO generates cos/sin at estimated carrier frequency
- Mixer: `I_bb = I×cos + Q×sin`, `Q_bb = Q×cos - I×sin`

**Trade-off:** Requires NCO and mixer before FFT, but simplifies subsequent processing.

---

## 10. Magnitude Squared for NCI Accumulation

**Decision:** Accumulate `I² + Q²` (magnitude squared) across NCI frames

**Explanation:**
- Non-coherent integration requires power (magnitude squared), not amplitude
- `mag² = I² + Q²` removes phase information, allowing coherent addition of power
- Avoids phase cancellation that would occur with complex addition
- Provides optimal SNR improvement for non-coherent integration
- Computed using DSP48 multipliers: `I² + Q²` in single cycle

**Trade-off:** Loses phase information (acceptable for acquisition) but maximizes sensitivity gain.

---

## 11. Testbench Stimulus: Realistic GPS Signal Simulation

**Decision:** Testbench loads pre-generated I/Q samples from hex files

**Explanation:**
- Stimulus files (`stim_i.hex`, `stim_q.hex`) contain realistic GPS L1 C/A signal
- Includes satellite signal + noise + potential interferers
- DC bias removal applied (mean I/Q subtraction)
- Allows realistic testing of acquisition algorithm
- Avoids complexity of real-time signal generation in testbench

**Trade-off:** Requires external signal generation tool but provides realistic test scenarios.

---

## 12. State Transition Monitoring in Testbench

**Decision:** Testbench prints state transitions and controller state for debugging

**Explanation:**
- Log shows: `[time] [DUT] STATE` and `[time] [CTRL] State -> X | Bin: Y | Freq: Z`
- Allows verification of correct state machine operation
- Confirms Doppler bin progression and frequency word updates
- Essential for debugging and validating acquisition algorithm
- Minimal overhead in testbench (just `$display` statements)

**Trade-off:** Adds simulation output verbosity but critical for verification.

## Conclusion

The design makes deliberate trade-offs favoring:
1. **Sensitivity** (20ms NCI, magnitude squared accumulation)
2. **Speed** (FFT-based parallel correlation)
3. **Precision** (parabolic interpolation for sub-chip resolution)
4. **Reliability** (FIFO buffering, clear state machine)

Resource usage is optimized for Xilinx Zynq architecture, leveraging DSP48 slices for math-intensive operations and BRAM for buffering/storage. The design is suitable for real-time GPS L1 C/A acquisition with ~1-2 second acquisition time for full sky search.
